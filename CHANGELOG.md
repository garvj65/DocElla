# Changelog

## [1.0.0] - 2026-08-12

### Added

- Three end-to-end workspaces: arbitrary-document extraction, fixed-schema PDF review, and schema-driven PDF creation.
- Shared declarative document definitions for Job Application and Basic Invoice.
- Dynamic frontend forms, review states, editing, validation, reset, cancellation, stale-result protection, and reviewed downloads.
- Validated generic ingestion for digital/scanned PDF, JPEG, PNG, BMP, TIFF, HEIF, DOCX, XLSX, PPTX, and HTML.
- Local PDF.js text/layout extraction for digital PDFs.
- Optional Azure Document Intelligence OCR/layout for scanned PDFs, images, Office documents, and HTML.
- Bounded generic schema discovery for sections, scalar fields, repeatable values, and flat tables.
- Groq discovery recovery across strict JSON Schema, best-effort JSON Schema, and JSON Object Mode while keeping local Zod validation authoritative.
- Strict generated JSON Schemas and bounded batching for generic value extraction on larger real-world documents.
- Deterministic local grounding with verified, needs-review, missing, conflicting, and low-OCR-confidence states.
- Privacy-safe provider diagnostics with request stage, status, provider error category, and bounded validation issue paths.
- A minimal Groq structured-output smoke command that sends no uploaded document content.
- Trusted AcroForm template generation through pdf-lib.
- Editable and flattened PDF downloads from both direct forms and reviewed extraction results.
- Redesigned bundled PDF templates with deterministic field typography, multiline behavior, and improved presentation quality.
- Safe binary response validation, filename sanitization, and temporary Blob URL cleanup.
- Same-origin production serving through Express.
- A multi-stage non-root Docker image with application health checks.
- Proxy-aware IP handling with bounded trusted-hop configuration.
- Bounded graceful shutdown with idle and forced connection cleanup.
- Compiled production smoke coverage and Docker CI verification.
- Deployment, operations, generic extraction, privacy, security, QA, and evaluator documentation.

### Reliability

- Generic provider input is bounded with deterministic head/tail sampling and payload-size backoff.
- Schema discovery and value extraction retry once after locally invalid model output.
- Discovery can recover from provider-side `json_validate_failed` failures without accepting unvalidated output.
- Larger discovered schemas are extracted in bounded batches and validated again after merging.
- Provider diagnostics preserve actionable metadata without logging document text or provider failed-generation content.
- Generated PDF form fields remove inherited length caps when those caps conflict with schema-valid values.

### Security and privacy

- Uploaded documents and generated PDFs remain memory-only and are not persisted by DocElla.
- Extraction and generation responses are non-cacheable.
- Logs exclude document bytes, complete source text, prompts, extracted/reviewed values, secrets, sensitive headers, query strings, generated bytes, and provider failed-generation payloads.
- Client input cannot choose arbitrary template paths, field mappings, output paths, or filenames.
- HTML and Office documents are never executed by the frontend.
- Extraction and generation have separate process-local rate limits.
- Provider credentials remain backend-only.

### Verification

- Formatting, lint, strict TypeScript, workspace tests, and release-build verification run in CI.
- Production CI builds and starts the Docker image, verifies `/api/health` and frontend delivery, and confirms non-root execution.
- Backend smoke commands cover provider configuration, mocked extraction, PDF generation, and compiled production serving.

### Known limitations

- No authentication or tenant isolation.
- No database, object storage, background queue, or resumable extraction jobs.
- Generic schemas are intentionally bounded to flat primitive fields and flat repeated tables rather than arbitrary nested structures.
- Generic extraction depends on model/provider reliability; local validation and fallbacks reduce but cannot eliminate failures for unusual documents.
- No user-uploaded PDF templates.
- Legacy Office binaries, password-protected files, audio, video, executables, and proprietary binary formats are unsupported.
- Source grounding exposes bounded snippets and locations rather than full visual coordinate highlighting.
- Process-local rate limiting is not distributed across replicas.
- Standard PDF appearance fonts may reject unsupported characters safely.
- Grounding verifies textual support and does not prove factual correctness.
